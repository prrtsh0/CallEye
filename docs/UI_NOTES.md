# UI Notes — deviations & decisions

This file records the decisions and deviations for the landing/app split. It is
the summary of what was actually built and where it differs from the evergreen
spec/goals. It intentionally does not duplicate `UI_SPEC.md`.

## 1. Two surfaces

- **Landing — `/`** (build output: `site/`,): public, no login, no microphone
  code, no service worker, no analytics. Pure static files.
- **App — `/app/`** (source: `app/static/app/`): the installable PWA. Hash
  routes inside it (`#/home`, `#/setup`, …). Opens in **Practice mode** by
  default. Live mode requires an access code.

### Deviation / note
- `UI_SPEC.md` does not exist in the repo yet. This document is the record of
  what was implemented for the split. When `UI_SPEC.md` is added, reconcile it
  against this file.

## 2. Routing (FastAPI)

| Path | Owner | Notes |
| --- | --- | --- |
| `/` | `site/` | landing, html=True |
| `/app` | `web/` | PWA, html=True, hash routes |
| `/shared` | `shared/` | shared ES modules + tokens |
| `/mic-test` | route | unchanged |
| `/healthz`, `/api/*`, `/ws/listen`, `/admin/usage` | API | unchanged |

The landing is served by FastAPI in this repo, but the content in `site/` is
self-contained (ES modules, no build step) with a single config value for the
app URL (`APP_URL`, default `/app/`).

## 3. Shared code (no duplication)

Lives in `shared/`:

- `tokens.css` — the design tokens (colours, type, shape).
- `fonts.css` — font imports.
- `doodles/` — brand doodles (SVG).
- `i18n-core.js` — shared language core.
- `result-view.js` — the shared result view + demo engine used by both the
  landing demo and the app. **Zero duplication** between landing and app.

## 4. Landing rules honoured

- Hero promise, doodle, buttons "Open the app" / "Watch a sample call".
- Demo plays `data/fixtures/demo_*.json` (three samples: digital-arrest,
  emergency claim, genuine bank) through the shared result view.
  - Captions always on; **sound only after a tap** (no autoplay).
  - "Flagged N seconds before the ask" is **computed from the fixture** by the
    shared engine, never typed in.
  - Zero network calls apart from static files.
- "How it works" (3 steps), who it is for, privacy promise, limits.
- Evaluation numbers shown **only if** `eval/report.md` exists (a build script
  writes `site/data/eval.json`). Hidden otherwise; never placeholder numbers.
- Footer: GitHub, docs, "Built with Gnani Prisma and Timbre". No "first/only/
  definite" wording. No analytics/trackers/external scripts.

## 5. App behaviour

- First run: welcome + setup wizard (local only). After that opens at Home.
- Visible mode badge: `Practice mode: no microphone, no credits` / `Live mode`.
- Live unlock: bottom sheet with a single access-code field → `POST /api/unlock`
  `{code}` → ok + daily allowance; **rate limited**. Code stored in
  localStorage only. The WebSocket start message carries it and the server
  validates it on every session. "Forget access code" in Settings = sign-out.
  No accounts/emails/passwords.
- **Empty `INVITE_CODES` means live mode is off.** Practice and upload modes
  work without a code.

### Deviation / note
- The old invite-code semantics (empty => open) are inverted: with the split,
  empty `INVITE_CODES` disables live entirely. Live requires `gnani_mode=live`
  **and** a non-empty `INVITE_CODES`.

## 6. PWA scope

- Manifest + service worker exist **only under `/app/`** (`scope: /app/`,
  `start_url: /app/`). The landing registers nothing.
- Demo: network-first service worker for the app shell.

## 7. Preview tags & image

- Landing `<head>` includes title, description, Open Graph and Twitter card
  tags.
- A `1200x630` preview image in the brand style (navy, doodle, name) is
  generated by a script and placed at `site/assets/og-image.png`.

## 8. Cold start

- If `/healthz` takes longer than ~2s when the app opens, the app shows
  "Waking up the app, one moment" (free-tier cold start).

## 9. Misc

- `mic-test.html` stays served at `/mic-test` and is not part of the landing.

## 10. Docs page

- A dedicated **Docs** page lives at `/docs` (`site/docs.html`), linked from the
  landing topbar and footer (FastAPI Swagger moved to `/swagger` so `/docs` is
  free).
- It documents what CallEye is, how the detector works, the verdict levels,
  privacy/limits, and the evaluation results (metrics + per-call table +
  misclassifications) rendered from `site/data/eval.json` — never typed-in
  numbers.

## 11. Backend-connected practice

- The app's **practice mode** now runs the **real Python detector**
  (`SessionAnalyzer`) instead of the browser-side JS approximation. The
  frontend `POST`s to a new endpoint `/api/practice/{fixture}`, which replays a
  stored fixture from `data/fixtures` through the actual detector and returns the
  same transcript/analysis event stream the live WebSocket relay emits.
- The landing page demo intentionally still uses the client-side engine (static,
  zero network, per the landing spec). The app is the surface connected to the
  model/backend.
- `POST /api/practice/{fixture}`: 404 for unknown fixtures; consumes zero
  credits (no STT/network).

## 12. "Done" definition

Open `/` on a phone → run the demo with no permissions → tap "Open the app" →
finish setup → try the practice call → enter an access code → start a live
session.
